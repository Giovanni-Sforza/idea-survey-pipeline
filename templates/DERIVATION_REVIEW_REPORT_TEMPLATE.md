## JSON sidecar schema

The accompanying `{ROLE}_review.json` file follows this schema:

```json
{
  "schema_version": "1",
  "role": "rigor | physics | literature | adversarial",
  "round": <int>,
  "verdict": "accept | revise | request_evidence | skipped",
  "score": <int 1-10>,
  "issues": [
    {
      "local_id": "<role>-I<NN>",
      "severity": "FATAL | CRITICAL | MAJOR | MINOR | OBSERVATION",
      "summary": "<one paragraph>",
      "minimum_fix": "<one paragraph>",
      "suggested_route": "alg | lit | scope | expansion | ignore",
      "affected_files": ["<path>:§<section>", ...],
      "affected_assumptions": ["<ladder_id>", ...]
    },
    ...
  ],
  "areas_checked_clean": [
    "<one-line description of an item you verified>",
    ...
  ],
  "evidence_needed": [
    {
      "claim": "<one-sentence claim>",
      "search_terms": ["...", "..."],
      "expected_outcome": "confirmed | refuted | partial"
    },
    ...
  ]
}
```

The router consumes ONLY the JSON sidecar for routing decisions; the
markdown file is for human review of the round's audit.
